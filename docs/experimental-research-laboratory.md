# InvestIQ experimental research laboratory

**Status:** executable, exploratory evaluation framework, not a validated comparative study. The [sample run](../experiments/lab/synthetic-example/report.md) uses simulated data and **heuristic test doubles, not LLMs**. No claim of superiority, originality, causal identification or investment profitability follows from it. E4 is a limited integration prototype; it is not the complete deployed financial intelligence architecture described in the [research design](investiq-research-design.md). This laboratory has not been run against real market data or a live LLM provider in this environment.

## Systems and comparison

All arms receive the same eligible origins, signal and point-in-time evidence. No future return, scenario truth, label timing, independent audit reference, delisting flag or other hidden dataset fields is passed to agent backends.

| Arm | Implemented system | Important limitation |
|---|---|---|
| E0 deterministic | Train-only ridge return prediction and logistic probability of a positive return; one deterministic evidence claim. | Simple statistical benchmark, not all conventional finance methods. |
| E1 single LLM + tools | One model request with deterministic, as-of financial tool results (signal, direction and, when available, unit-matched net cash flow/net worth). | The optional backend passes precomputed tool outputs in the prompt; it does not implement open-ended tool calling. |
| E2 consensus | Three independent role-conditioned requests; mean probability/return, aggregate claims; report does not display individual conclusions. | Roles are not independent experts; identical weights/sources/models may yield correlated errors. |
| E3 disagreement-preserving | Same three roles and mean aggregation, plus original agent conclusions and Jensen–Shannon divergence retained in each report. | In the deterministic fixture E2 and E3 have identical probabilities; preservation alone does not prove a forecast gain. Live calls are separate, so variability/cost confounds comparisons unless a stronger matched/replayed design is registered. |
| E4 unified prototype | E3-style preserved positions, online exponentially smoothed signal state, a fixed linear-Gaussian ECCR scenario via Monte Carlo, validation-only calibration, provenance checks and outcome records. | The simple signal state is **not** the full TFSF investor twin. ECCR coefficient/independence are assumed, and claims are numerically cross-checked, not semantically validated. No full production evidence ledger or autonomous research system is claimed. |

The simulated backend is explicitly named `synthetic-heuristic-not-an-llm`, is restricted to synthetic datasets and cannot masquerade as the live backend. Its role-dependent probabilities and occasional citation errors are generated deterministically from seed/role/entity/origin. All three multi-agent roles see the same sanitized snapshot, no peers, and no outcome. E2/E3/E4 require three calls per origin and E1 one; actual token and latency costs are reported, but this is **not** a matched token-budget study. No source diversity or independent pretraining is assumed.

For a real LLM run, use `--backend live --model-version <immutable-provider-model-version>` and provide `INVESTIQ_LLM_ENDPOINT` (complete HTTPS chat-completions URL), `INVESTIQ_LLM_ALLOWED_HOSTS` (comma-separated exact hostnames) and `INVESTIQ_LLM_API_KEY` through a trusted secret manager. Endpoint redirects are disabled. Only the allowlisted financial tool snapshot and as-of evidence are sent. Requests require a JSON response with `probability`, `expected_return`, `scenario_effect`, and up to 20 claims (`evidence_id`, `metric`, `unit`, `value`). Invalid responses or provider errors fail the whole run, rather than dropping hard cases. The failed arm and error **type** are logged to MLflow with a failed status; error messages are omitted from the stored failure record. Schema validation errors occurring before an experiment starts do not create an MLflow run. Explicitly authorize sending data to the provider; filings may contain adversarial prompt injection and hosted model weights can contain post-origin knowledge. No live provider or genuine historical LLM comparison was tested here. Do not send private financial data or restricted licensed evidence without legal, privacy and security review.

## Installation and reproducible example

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -m pytest -q

# Separate selection (no test forecasts or scores) from the locked final run:
python -m investiq.lab --stage selection --seed 42 --days 60 --output results/lab-selection
# Only after registering decisions, freeze the configuration and use the final test once:
python -m investiq.lab --stage final --seed 42 --days 60 --output results/lab-final
# Illustrative preregistered E4 ablation; use a separate empty output directory:
python -m investiq.lab --stage selection --ablation no_state_update --seed 42 --days 60 --output results/lab-ablate-state
```

Each output directory must be empty, so a run cannot overwrite an earlier result there. A synthetic example is provided under `experiments/lab/synthetic-example/`, including a Markdown report, complete JSON record, CSV tables and LaTeX tables. It is a single illustrative seed, not a statistically powered study. The example's synthetic scenario truth uses the exact 0.3 coefficient that E4 assumes; its scenario error is a wiring check and is **not a blinded benchmark**. The tables explicitly identify the synthetic backend.

Outputs: `report.json` (configuration, code/dependency hashes, data hash, metadata, metrics, limitations, comparison CIs and per-origin predictions/claims), `report.md` (tables, negative findings and limitations), `results.csv`/`.tex`, compact `forecast_metrics.tex` and `evidence_risk_metrics.tex`, `comparisons.csv`/`.tex`, `mlflow_run_id.txt`, and a local `mlruns/` store. MLflow records parameters, numeric metrics, computational costs, paired p-values and the report, metric tables and comparison artifacts. Default tracking is the local output directory; no implicit remote MLflow server is used. This means running in different output directories creates separate local MLflow stores. Configure access-controlled storage and an explicit reviewed tracking architecture for shared use; this code intentionally does not push to one. Reports can contain claims, values, entity IDs and outcomes: protect and retain them under the source and privacy rules, even if they are local. `results/` is Git-ignored.

Records include the dataset version and canonical SHA-256, declared model version/backend, UTC execution timestamp, seed, all configuration, split counts/exclusions, metrics and limitations, key library versions, laboratory source hashes, ECCR source hash and requirements-lock hash. Inference runtime and peak Python allocations are measured per arm over validation plus evaluation; the separately reported baseline fit time does not include all infrastructure or GPU/provider resource use. Exact hosted-model regeneration is not guaranteed; model version, pretraining cutoff, prompt, provider backend changes, hardware and SDK should be independently archived. Provider token prices are explicitly configured USD per million input/output tokens; `cost_per_research_report_usd` is inference-provider cost only, excludes compute, personnel, infrastructure and validation calls, and is `null` if price or usage is unknown. The synthetic backend's provider cost is zero, not zero real-world cost. Validation cost and token counts are reported separately.

## Dataset contract and temporal controls

For a custom dataset pass `--dataset path.json --train-end <UTC> --validation-end <UTC> --test-end <UTC>`. The JSON has a `dataset_version`, `dataset_kind` (`synthetic` or `historical`), `universe_source`, `license`, explicit booleans `membership_includes_delisted` and `delisting_returns_complete`, and a `rows` array. Both booleans must be true, but they are operator **attestations**, not proof of complete coverage. In practice, retain the independently licensed historical security master, constituent changes, instrument IDs, corporate actions, delistings and exit proceeds; audit gaps before research. Surviving-only universes or missing terminal returns are rejected, not silently treated as complete.

Each row contains:

- Stable `entity_id`, timezone-aware `origin`, `member_at_origin: true` and membership availability/retrieval instants no later than origin.
- `signal` (fraction), and at least one `evidence` entry with the exact same numeric signal and unit `fraction`. Each evidence entry has `id`, `source`, `metric`, `value`, `unit`, `published_at`, `available_at`, `retrieved_at`, `version_identifier`, and `validation_status: "valid"`; availability must follow publication and availability/retrieval must not be later than origin. Entries must have unique IDs within a row. The same metadata is required for each independent `verification_references` entry, which may be an empty array. References are withheld from the model and should be independently sourced; different source names are not proof of independence.
- `future_return` (fraction, at least -1), plus timezone-aware `label_available_at` strictly after origin and `label_retrieved_at` no earlier than availability. An exit row must have `delisted_after_origin: true` and `exit_return_included: true`; the return must include actual proceeds/loss under a documented data convention. Missing exit data must not be replaced with zero. Label values and verification references are never sent to the model. These truth/label fields must come from a source that can be legally stored and audited.
- `scenario_shock` between -1 and 1 is a **hypothetical input**, not a future observation. `scenario_truth` may be omitted or null unless an independently defensible intervention benchmark or synthetic ground truth exists. Do not invent a real counterfactual from the realized factual outcome; `scenario_error` is `null` when no ground truth exists.

The full schema is enforced in `investiq/lab/data.py`; `synthetic()` is an executable reference example. Data must be built from licensed, versioned inputs, such as the point-in-time evidence infrastructure; this repository does **not** yet provide an automatic snapshot-to-panel join or a historical universe provider. Times, provenance, independent audit references and survivorship completeness are inputs and require external verification. Dataset validation catches obvious timing/identity errors, not vendor timestamp fraud, pretraining contamination, membership omissions or data snooping.

The boundaries are chronological and strictly increasing. Train includes origins `<= train_end`, validation origins `> train_end` and `<= validation_end`, test origins `> validation_end` and `<= test_end`. A row is purged if its outcome was not both available and retrieved by its own split end; counts are reported. There are no shuffled folds, cross-boundary label windows, imputation of missing terminal outcomes or full-data standardization. E0 fits train only. The `selection` stage computes **uncalibrated** validation results and never calls agents on or scores test rows; its schema validation and whole-dataset hash still inspect the dataset file, so physically isolate the sealed test set for stringent studies. Select and register the specification using development/validation, including costs, blocks and all ablations. The `final` stage fits Platt/logit calibration on validation only (if there are at least 10 observations and both event classes), then evaluates fixed models on test. Test outcomes are never used for fitting, calibration, thresholds or automatic model selection. Selecting a model, feature, ablation, seed, cutoff or report after observing final outcomes is still researcher-driven leakage; output-directory safeguards cannot prevent it across runs. Lock the protocol before unsealing and keep a truly untouched final replication. Nested development/validation is needed if validation itself is repeatedly reused for tuning and calibration.

## Metrics, inferential protocol and reporting

- **MAE/RMSE:** return forecast vs realized one-period return, pooled issuer-origin observations. **Brier:** squared error for `return > 0`; **log loss:** event probability clipped to `[10^-6, 1-10^-6]`. **ECE:** fixed ten equal-width probability bins; it is descriptive and sensitive to bins/sample size. Platt scaling is not a guarantee of calibration.
- **Maximum drawdown:** maximum peak-to-trough decline of an illustrative long-only test portfolio. Each origin, a positive-event probability at least 0.5 is selected; equal weights capped at 0.25 per entity, unallocated capital is cash, and `cost_bps` is charged on absolute change in target weights including initial entry and final liquidation. Gross leverage is at most 1. This is an approximate constant-target-weight turnover calculation, not drift-adjusted execution: no spreads beyond the configured rate, financing, market impact, liquidity, exchange calendars, taxes, borrow or capacity are modeled. **Risk-constraint violations** count dates with actual output weights outside the long-only/gross/position constraints; by construction this will normally be zero. Predictions and positions are not investment recommendations.
- **Evidence coverage:** fraction of reports with at least one claim exactly matching its cited as-of evidence under numerical tolerance. **Unsupported claim rate:** fraction of all claims without a matching independent-source reference (including missing references and invalid citations); no claims yields `null`, not zero. `source` names differing is necessary but not sufficient for independence. Neither metric establishes semantic support, completeness, authenticity or causal validity.
- **Scenario error:** mean absolute error of scenario-effect estimates on rows with explicitly supplied scenario truth; the scored count is reported. Synthetic assumptions and real interventions are different scientific claims. No individual counterfactual ground truth is inferred from observed prices.
- **Cost per report:** mean actual/configured provider token cost on scored reports; null when usage or pricing is unknown. Training/validation token costs and Python elapsed time/peak allocations are separately tracked. These are not total economic costs.

For each E1–E4 arm versus E0, the paired Brier loss difference is first averaged across entities for each origin date. Moving-block bootstrap resamples whole dates (all entities together), with preconfigured seed, 1,000 default replicates and length five. `comparisons.csv/.tex` report a 95% percentile interval, a two-sided centered-bootstrap approximate p-value, Holm-adjusted p-value across the four arm-vs-E0 comparisons, number of dates and paired rows. The CI is not multiplicity-adjusted. Small numbers of dependent dates, nonstationarity and block choice can make inference unreliable; these p-values are **exploratory**, not universal significance guarantees. The main metric table averages issuer-origin rows; the paired comparison uses equal weight per date, so their numerical differences need not match. Record negative results for each reported loss/risk/cost and lower evidence coverage against E0, including nonsignificant results; do not equate statistical significance with economic significance. No trading return is used to select a model here.

## Ablations and limitations

`--ablation` is an E4-only switch: `no_state_update` uses the contemporaneous signal instead of the smoother; `no_scenario_simulation` uses the agent scenario mean; `no_calibration` disables validation Platt scaling for E4; `hide_dissent` hides presentation but retains original agent outputs in the immutable report record. Run the default and all registered ablations separately with identical data/splits/seeds and suitable controlled LLM inputs. Disabling a component does not isolate its effect if model prompts, random outputs or token budgets differ. A final test should execute only ablations preregistered before the holdout is unsealed; use a separate replication for new ideas.

The framework deliberately does not provide real-time trading, legal data acquisition, execution, financial advice, model-risk approval, external LLM identity verification, a semantic claim verifier or an independently identified causal benchmark. Publication requires stronger conventional financial baselines, genuinely independent live/prospective LLM evaluations, verified historical universes and timestamps, robust costs and corporate actions, multiple periods/seeds, power analysis, sensitivity to dependence, preregistration, leakage checks and independent replication. Preserve null and negative findings.
